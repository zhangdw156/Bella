# Bella Benchmark 评测报告

## 实验概述

- **日期**: 2026-05-10
- **Case 数量**: 148（经过 16 轮收敛测试，删除 39 个饱和 case 后）
- **重复次数 (n)**: 8
- **并发度**: 80
- **User 模型**: gpt-5.2（两组实验共用）

| 配置 | React 模型 | 协议 | 系统提示词 |
|---|---|---|---|
| 实验 A | gpt-5.2 | OpenAI | 改进版（强制立即调用工具） |
| 实验 B | claude-opus-4.5 | Anthropic 原生 | 改进版（强制立即调用工具） |

### 关键方法论说明

1. **原生协议**: Claude Opus 4.5 使用 Anthropic 原生 SDK 调用（非 OpenAI 兼容代理）。前期实验证明代理层会丢失 tool_use blocks，导致 pass@1 下降约 28 个百分点。
2. **系统提示词**: 经过优化，核心改动为强制模型在需要工具时立即发出 tool call，禁止只表达意图而不实际调用。
3. **饱和 case 删除**: 通过 4 轮收敛测试（n=4/8/12/16），识别并删除了 39 个两模型都 16/16 通过的 case，确保剩余 case 都有区分价值。

### 分类特征分析

- **bfclv4_vehicle（差距最大 +42.5）**: vehicle 环境有 startEngine 前必须 lockDoors 的硬约束。GPT 遇到错误后倾向于等用户指令，Opus 则主动修复并重试。
- **bfclv4_travel（+30.0）**: 涉及多步骤预订流程（查航班、订票、买保险），Opus 的工具调用链更完整。
- **bfclv4_trading（+18.8）**: 股票交易操作，Opus 在多步骤计算（价格比较、金额推算）上更准确。
- **bfclv4_filesystem（+14.1）**: 文件系统操作，Opus 在路径导航和前置步骤方面更可靠。
- **tau3_retail（+6.4）**: 动态交互模式，user agent 引导弥补了 GPT 的自主性短板，差距缩小。
- **mcpmark_postgres（+2.7）**: 数据库操作，两模型表现接近。
- **tau3_airline（+0.0）**: 动态交互模式，两模型完全持平。

## 五、关键发现

### 1. Opus 4.5 全面优于 GPT-5.2

在公平条件下（各自原生协议 + 相同提示词），Opus 4.5 的 pass@1 为 72.0%，高于 GPT-5.2 的 61.3%（+10.7）。pass^8 差距更大（42.8% vs 26.0%，+16.8），说明 Opus 不仅更强，稳定性也更高。

### 2. 错误恢复能力是核心差异

BFCL 环境的 case 揭示了最大的差异来源：当工具调用返回错误时，Opus 倾向于立即自主修复并重试，GPT 倾向于等待用户指令。在 fixed 模式（无用户追问）下，这个差异被放大。

### 3. 交互模式影响差距

- **Fixed 模式**（BFCL 系列）：差距大（+14 到 +42），因为模型必须自主完成全部操作
- **Dynamic 模式**（tau3 系列）：差距小（0 到 +6），因为 user agent 会引导和追问

### 4. 协议选择至关重要

前期实验证明，Claude 模型通过 OpenAI 兼容代理调用时，pass@1 仅 47.7%；切换到原生 Anthropic 协议后提升到 76.3%（+28.6）。代理层在格式转换中丢失了 tool_use blocks，是性能骤降的根本原因。评测框架必须使用模型的原生协议。

### 5. Benchmark 质量验证

经过饱和 case 删除后，148 个 case 的有效区分率达到 86%。Benchmark 能有效区分模型在工具调用、错误恢复、多步推理等维度的能力差异。
